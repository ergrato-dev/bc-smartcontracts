# 🌐 Webgrafía — Semana 03

| Recurso | Descripción |
| ------- | ----------- |
| [Solidity — Introduction to Smart Contracts](https://docs.soliditylang.org/en/v0.8.38/introduction-to-smart-contracts.html) | Oficial. Un contrato de almacenamiento simple explicado línea a línea: lo mismo que el `Counter` |
| [Solidity — Layout of a Source File](https://docs.soliditylang.org/en/v0.8.38/layout-of-source-files.html) | Oficial. Licencia SPDX, `pragma` e `import` |
| [Solidity — Structure of a Contract](https://docs.soliditylang.org/en/v0.8.38/structure-of-a-contract.html) | Oficial. Variables de estado y funciones; lo demás llega en las semanas siguientes |
| [Foundry — Forge overview](https://getfoundry.sh/forge/overview) | Oficial. Qué hace `forge` y cómo se organiza un proyecto |
| [Foundry — Project layout](https://getfoundry.sh/projects/layout) | Oficial. Las carpetas de un proyecto, como en la Teoría 02 |
| [Foundry — Tests](https://getfoundry.sh/forge/tests/overview) | Oficial. Cómo escribe y ejecuta tests `forge` |
| [Foundry — Deploying](https://getfoundry.sh/forge/deploying) | Oficial. `forge create` y sus opciones |
| [Foundry — cast call](https://getfoundry.sh/cast/reference/call) y [cast send](https://getfoundry.sh/cast/reference/send) | Oficial. Todas las opciones de los dos comandos de la Teoría 05 |
| [Foundry — prank](https://getfoundry.sh/reference/cheatcodes/prank) y [expectRevert](https://getfoundry.sh/reference/cheatcodes/expect-revert) | Oficial. Los cheatcodes de esta semana |
| [ethereum.org — Anatomy of smart contracts](https://ethereum.org/developers/docs/smart-contracts/anatomy/) | Datos, funciones y visibilidad, con ejemplos cortos |
| [ethereum.org — Compiling smart contracts](https://ethereum.org/developers/docs/smart-contracts/compiling/) | Bytecode y ABI, el resultado de compilar (Teoría 01) |
| [Solidity by Example](https://solidity-by-example.org/) | Contratos mínimos por tema. Esta semana: *Hello World*, *First App*, *State Variables* |

Cada recurso oficial va primero porque es el que se mantiene al día con la versión. Los
ejemplos externos pueden usar `pragma ^0.8.x`: en el bootcamp, siempre `0.8.38` exacto.
